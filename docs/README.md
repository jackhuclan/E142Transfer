# 半导体 Wafer Map 知识文档

本目录整理自一次连贯的技术讨论，主题围绕"晶圆测试结果如何变成可传递、可追溯的晶圆图数据"，并最终落到本工程的 `.NET 10` 实现。

## 知识脉络

```
点墨（物理标记）
  → bin 编码（测试结论分档）
    → BinCode（码值→语义的字典）
      → SEMI E142 文件结构与 MapType（数据怎么存）
        → TransferMap + KGD（数据怎么跨站追溯）
          → 常见格式与 Artwork（现实世界的格式生态）
            → SINF（结果级）与 KLARF（缺陷级）两条数据线
              → SEMI G85（Amkor/Camtek 老牌 probe 数据）与 Marked Bin 陷阱
                → TSK 探针台 DAT（逐 die 二进制：幅值坐标 + 状态位 + 配对 XTR 的 bin 表）
                  → AOI 缺陷清单 KLARF（die 图无 bin：类别只能由缺陷聚合出来）
                    → 本工程的适配器实现
                      → AOI 设备侧：运动控制抽象层（15）与 IO/光源/触发时序（16）
                        → AOI 光学成像：相机/远心镜头/LED 明场暗场/滤光片轮（17）
                          → 光源控制器：恒流驱动、通道、接口与频闪操控（18）
                            → 用 C# 落地 IO 控制：契约/点表/轮询事件/错误处理（19）
                              → 可复用光源控制器：ILightController / ILightDeviceTransport（21）
                                → IO 控制层工程实现：WaferMapStudio.Io + 真实点表解析（22）
```

## 阅读建议

- **只想建立直觉**：读 01 → 20（一张图看懂 die 是格子、bin 是格子里的字）→ 03 → 06。
- **要写解析器**：读 02 → 04 → 05，再直接看 09 的代码说明。
- **要对接设备/MES**：重点读 04（坐标与 reference die）、06（TransferMap 与 ID+Map）、07（格式生态）、10（SINF 1-based 陷阱）、12（G85 数字码原点与转置）、13（TSK DAT 二进制记录与 XTR 对账）。
- **要接 AOI 缺陷数据**：读 11（结构理论）→ 14（真实样本，含 die 级 bin 的推导口径与 14 类告警），再按 09 的"新增格式三步法"扩展 Reader。
- **要接 Amkor/Camtek G85 数据**：读 12，并直接用 `amkor-g85-ingest` 技能按五步流程处理。
- **要扩展本项目**：从 09 开始，按其"新增格式三步法"操作。
- **要理解设备侧控制链路**：读 15（运动轴如何被抽象控制）→ 16（IO 模块如何采集传感器、驱动光源/阀、做飞拍触发与安全联锁）→ 19（用 C# 把 IO 控制真正落地：契约/点表/轮询事件/错误处理）→ 17（成像链上相机/镜头/光源/滤光片怎么配合）→ 18（光源控制器如何接线、调光、做频闪同步，并与 16 的飞拍时序对照）→ 21（如何用 C# 把光源控制器做成可复用抽象层、接入真机）。

## 与上位机的关系

这些概念对应 PL 检测上位机中的 EL / PL / AOI 三映射：

- 每一张 mapping 本质就是一张"光学域的 wafer map"；
- 每个 die 的 pass/fail/缺陷类别就是一种 bin；
- 三张图的叠加与一致性比对，等价于电性测试中的 multi-bin 交叉分析；
- **EL / PL 是结果级数据**，对应 E142 / SINF 链路；**AOI 是缺陷级数据**，对应 KLARF 链路，两类数据在 `NeutralWaferMap` 汇合；
- 归档与对外交付时，用 E142 作为统一载体，用 TransferMap 承接跨站追溯。
