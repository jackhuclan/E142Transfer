# 04 SEMI E142 文件结构

[返回索引](./README.md)

## 标准定位

**SEMI E142**（2005 年批准）是无墨点晶圆图标准，基于 **XML**，定义一颗 die 的结果如何被编码、存储和跨厂传递。它覆盖 wafer、film frame、strip、tray 多种载体，把 bin 码以 overlay 形式附加，并支持 transfer map。

## 三大块结构

```
MapData
 ├─ Layouts / Layout            # 定义 die 网格坐标系
 │    └─ Dimension (X=Columns, Y=Rows)
 │    └─ StepSize (X, Y)
 │    └─ ProductId
 ├─ Substrates / Substrate       # 描述载体本身
 └─ SubstrateMaps / SubstrateMap # 真正的数据区
      └─ Overlay (MapName, MapVersion)
          ├─ BinCodeMap (BinType, NullBin, MapType)
          │    └─ BinDefinitions / BinDefinition
          ├─ DeviceIdMap
          ├─ DeviceDataMap
          └─ TransferMap (FromSubstrateType, FromSubstrateId, ...)
               └─ T (FX, FY, TX, TY, FID, TID)
```

- **Layouts**：定义列数、行数、die pitch、原点位置（默认 LowerLeft）、轴方向（默认 UpRight）、notch/flat 朝向。
- **Substrates**：支持 wafer、frame、strip、tray 四类载体（E142 后续版本还扩展到 tape & reel、panel、PCB）。
- **SubstrateMaps**：真正的数据区，用 Overlay 承载 bin 码阵列和参考 die。允许一张文件里定义多个 Overlay（例如同时有 SortGrade 和 VisualInspection 两张图）；MPW 多产品晶圆还能链接多个 Layout。

## Bin 码的物理编码格式

同样是"一格一个结果"，有四种合法写法，混用会直接解析错位：

| BinType | 码值形态 | 分隔方式 |
|---|---|---|
| Ascii | 单个字符，如 `P` / `X` / `.` | 无分隔，按字节切 |
| Decimal | 3 位十进制，如 `001` | 无分隔，定宽切 |
| Hexadecimal | 2 位十六进制，如 `FF` | 无分隔，定宽切 |
| Integer2 | 2 字节整数 | 二进制定宽 |

**只有 Decimal 才可能有空格分隔**；ASCII/Hex/Integer2 是无分隔连续串。用错分隔方式整行错位。

## 关键字段与解析要点

### 坐标与朝向

文件头里 `OriginLocation`（默认 LowerLeft）和 `AxisDirection`（默认 UpRight）决定行列索引怎么映射到物理位置，`Orientation="180"` 表示相对 notch 的旋转。

如果文件里没写 origin/direction，解析器只能按默认值猜——这是很多 map 旋转错位的根源。

### Reference die（参考 die）

**必须有**。它记录参考 die 在阵列中的索引位置和距晶圆中心的距离，后面 die sorter 就是靠它把 map 和切割贴膜后的 physical die 对齐。设备上线前必须用参考 die 和几个已知失效位置做一次目视/视觉比对，确认对齐——这一步不能省，也不能假设。

典型文件有 1、2 或 4 个参考 die。

### BinCode 定义表

至少要有 NullBin、Pass、Fail 三类，扩展的失败类型、alignment die、test device 都可以各自占一个码。详见 [03 BinCode](./03-BinCode-码值到语义的映射.md)。

### Transfer map

把 strip/tray 上每颗 die 反查回原始 wafer 坐标。先进封装里 die 经过多次搬运重排，出了 field failure 要追溯回源头晶圆，就靠这张图。详见 [06 TransferMap 与 KGD 追溯链路](./06-TransferMap与KGD追溯链路.md)。

### 与 KLARF 的区别

**KLARF**（KLA 缺陷报告格式）是分节文本（HEADER / CLASS LOOKUP / INSPECTION TEST / SAMPLE TEST PLAN / DEFECT RECORD），比 E142 多记录了**缺陷在 die 内部的位置**（XREL/YREL）和缺陷图像指针，属于"缺陷级"数据；E142 是"结果级"数据，每个 die 一个码。

对应到上位机：AOI 缺陷数据更接近 KLARF 那一类，EL/PL 逐 die 判定更接近 E142。

## 写解析器的实用提醒

- **不要假设编码类型**：BinType、MapType 都可能不是默认值，必须先读文件头声明。
- **Decimal 才有空格**：其余按固定字节宽切分。
- **NullBin 不对称**：2DArray 要显式填满空位，Row/Column 则跳过不存在的 die——两种排布的阵列长度含义不同。
- **Beyond 256 bin**：KLARF 的 CLASS LOOKUP 可以超过 256 类，但多数 map 格式只支持 256 个 bin（还要留出 Null 和 Pass），转换时要做合并映射。
- **命名空间版本差异**：各厂 E142.1 URI 不同（V1005 / V1016 / V0225…），解析器应按 `LocalName` 匹配，不要绑定固定命名空间。
