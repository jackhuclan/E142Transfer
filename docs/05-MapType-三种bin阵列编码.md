# 05 MapType：三种 bin 阵列编码

[返回索引](./README.md)

## 定义

SEMI E142 定义了 **MapType**，规定同一张晶圆图的 bin 码阵列"怎么摆"。三种方式表达的信息完全相同，区别只在编码效率和可读性。

（E142.1-0225 另增 `Coordinate` 类型，即每个 bin 自带 X/Y 属性，本工程已支持。）

## 1. 2DArray（默认）

最直观、最易读。**每一行 die 就是一个 BinCode 条目**，行内 bin 码连续排列，行数 × 每行长度必须严格等于 Layout 里声明的 Columns × Rows。圆形晶圆落在方形阵列里，那些"没有 die 的位置"（四角、边缘）必须显式填 NullBin。

```
0000000      ← 第1行全是空位
000UXYX      ← 第2行：3个空 + U X Y X
00UUUUU
```

优点是人眼可直接看出晶圆形状；缺点是空位也要占位，数据冗余。

## 2. Row / Column（行/列式）

**只记录有 die 的片段**：每行给出一个起始坐标（X, Y）、一个长度 N、然后 N 个 bin 值。

```
003 001 4 U X Y Z    ← 从 (3,1) 开始，连续4颗：U X Y Z
002 002 5 U U U U U  ← 从 (2,2) 开始，连续5颗
```

优势很明确：**不必列出 Null 位置**（跳过的都是空位），文件更小；而且规范允许各片段顺序任意——只要起始坐标正确，解析出来的图就对。这在只测了部分 die（抽样测试）时特别省事。

## 3. Array Format（一维长串）

把整个阵列拍平成一个长字符串，不换行、没有行结构。读软件**已知列宽和行数**，自己按长度切分成行。规范说阵列从左上角开始。

```
000000000UXYX00UUUUU0UXXYXX...
```

最紧凑，但可读性最差——离了 Layout 的列宽根本没法人工解析，而且它与 `ArrayOrigin` 等参数如何交互在不同实现里有歧义。

## 对比与选择

| 维度 | 2DArray | Row/Column | Array Format |
|---|---|---|---|
| 空位处理 | 显式填 Null | 跳过不写 | 显式填 Null |
| 可读性 | 高（肉眼可辨形状） | 中 | 低 |
| 文件体积 | 中 | 小（抽样时最优） | 最小 |
| 行顺序 | 必须按序 | 可乱序 | 固定 |
| 依赖信息 | 行列数 | 起点坐标 | 列宽 + 行数 |

**未声明 MapType 时默认 2DArray**，这是解析器的兜底分支。

## 对上位机的提醒

三种都是合法 E142 文件，导入模块**三种都得支持**，不能只按 2DArray 写。解析分支的关键判断点：

- 先读 MapType 声明，没读到一个就走 2DArray 默认分支；
- 2DArray 和 Array Format 都要用 Layout 的 Columns 去切行，区别在于前者已有换行、后者没有；
- Row/Column 要按"起点 + 长度"随机写入二维数组，不能假设输入有序；
- 三种都要把 Layout 声明的 OriginLocation / AxisDirection 应用到索引到物理坐标的映射上——否则编码对了、图却是转的。

本工程的 `E142MapReader` 已支持 2DArray / Array / Coordinate，Row/Column 会写入 `ImportIssue` 提示，见 [09 工程实现](./09-工程实现-E142Transfer适配器.md)。
